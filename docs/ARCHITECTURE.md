# 인생네컷 웹서비스 설계도

## 1. 목표

서버 프로그램(웹사이트의 요청을 받아 처리하는 별도 프로그램) 없이 HTML·CSS·순수 JavaScript 파일만으로 웹서비스를 만듭니다. 사진 파일을 보관하는 기능만 Supabase Storage(온라인 파일 보관함)를 사용합니다.

1단계에서는 카메라를 켜고 사진 한 장을 촬영해 화면에서 확인합니다. 확장 A에서는 2컷 또는 4컷을 자동 촬영해 세로 프레임으로 만듭니다. 필터, 온라인 보관과 QR 받기는 표시된 후속 확장에서 추가합니다.

## 2. 세 층 구조

| 층 | 맡은 일 | 파일 |
|---|---|---|
| 화면 층 | 버튼, 카메라 미리 보기, 촬영 사진과 결과를 휴대폰 세로 화면에 보여 줍니다. | `index.html`, `style.css` |
| 기능 층 | 버튼 동작, 카메라 촬영, 여러 컷 합치기와 필터 적용을 처리합니다. | `js/app.js`, `js/camera.js`, `js/frame.js`(확장 A부터), `js/filters.js`(확장 B부터) |
| 저장 층 | Supabase 연결 설정, 완성 사진 보관, 사진 주소를 QR 코드로 보여 주는 일을 처리합니다. | `js/config.js`(확장 C부터), `js/upload.js`(확장 C부터), Supabase Storage(확장 C부터) |

## 3. 화면 흐름

```text
컷 수 고르기(확장 A: 2컷 또는 4컷)
  → 시작 버튼 한 번 누르기
  → 각 컷마다 5, 4, 3, 2, 1 카운트다운
  → 사진 촬영, 진행 표시 갱신, 썸네일 추가
  → 다음 컷이 있으면 촬영 완료부터 다음 카운트다운까지 최소 700ms 간격 확보
  → 선택한 컷 수만큼 반복
  → 촬영 순서대로 쌓은 흰 세로 프레임 결과 확인
  → 처음으로: 선택·사진을 비우고 새 세션 시작
  → 필터 고르기(확장 B부터, 촬영 사진에만 적용)
  → Supabase Storage에 보관하고 QR 코드로 받기(확장 C부터)
```

촬영 화면은 `현재 컷 번호 / 전체 컷 수` 형식(예: `1 / 4`)으로 진행 상황을 표시합니다. 촬영한 컷마다 썸네일을 추가합니다. 오류가 발생하면 결과 화면으로 넘어가거나 성공한 것처럼 보이게 하지 않고 화면에 안내를 표시합니다.

다음 컷이 남아 있을 때의 700ms는 촬영이 완료된 시각부터 다음 카운트다운이 시작되는 시각까지의 최소 간격입니다. 촬영 직후 썸네일 추가 등 부가 처리에 걸린 시간도 이 간격에 포함합니다. 처리 후 경과 시간을 계산해 `max(0, 700ms - 경과 시간)`만 기다리므로 부가 처리 시간이 700ms에 더해지지 않습니다. 마지막 컷 뒤에는 다음 촬영이 없으므로 기다리지 않습니다.

1단계에서는 카메라 영상과 사진 한 장 확인까지가 구현 범위입니다. **실제 기기/브라우저에서 카메라 권한, 영상 표시 및 촬영을 확인하는 검증은 아직 남아 있습니다.** 이 검증은 확장 A의 설계·구현 완료와 별개의 1단계 확인 항목이며, 아직 완료된 것으로 간주하지 않습니다.

## 4. 부품과 함수

|---|---|---|---|---|

| `js/app.js` | `selectCutCount(count)` | 선택한 컷 수 `2` 또는 `4` | 갱신된 선택 상태 | 선택된 컷 수를 저장하고 선택 화면에 표시합니다. |
| `js/app.js` | `startSession()` | 없음 (저장된 컷 수와 화면 요소 사용) | 촬영 완료 또는 실패를 나타내는 Promise | 선택한 컷 수를 확인하고 새 촬영을 시작합니다. 촬영 순서를 초기화하고 `runCaptureSequence()`를 실행합니다. |
| `js/app.js` | `runCaptureSequence()` | 없음 (선택된 컷 수, 카메라 영상 요소 사용) | 촬영 완료 또는 실패를 나타내는 Promise | 매 컷마다 `runCountdown()` 후 `captureShot(video)`를 호출하고, `1 / 4` 형식 진행 상황 및 썸네일을 갱신합니다. 다음 컷이 남았을 때는 직전 촬영 완료부터의 경과 시간을 반영해 700ms 간격의 남은 시간만 기다립니다. 모두 촬영하면 `renderResult()`를 호출해 원본 필터의 결과를 보여 줍니다. |

| `js/app.js` | `resetSession()` | 없음 | 새 세션 상태 | 선택 컷 수, 촬영 목록, 썸네일과 결과를 비우고 컷 선택 화면으로 돌아갑니다. 다음 촬영은 이전 데이터가 없는 새 세션입니다. |
| `js/app.js` | `showError(message)` | 사용자에게 안내할 오류 메시지 | 오류 안내 표시 완료 신호 | 카메라 권한 거부, 촬영 등 실패를 화면에 설명하고 다음 행동을 안내합니다. 내부 오류를 성공 결과처럼 표시하지 않습니다. |
| `js/filters.js` | `FILTERS` | 없음 | 필터 정의 목록 | 각 항목은 `name`, 화면에 표시할 `label`, 픽셀의 RGB 값을 바꾸는 `apply(r, g, b)` 함수를 가집니다. 확장 B의 필터 6종과 변환 방식은 아래 표와 같습니다. |
| `js/filters.js` | `applyFilter(canvas, filterName)` | 사진이 그려진 원본 캔버스와 필터 이름 | 필터 결과가 그려진 새 캔버스 | 원본 캔버스와 같은 크기의 새 캔버스를 만들고 선택한 필터를 적용합니다. 입력 캔버스는 읽기만 하며 변경하지 않습니다. |
| `js/upload.js` | `uploadPhoto(canvas)` | 완성 사진이 그려진 캔버스 | 업로드된 사진의 URL(인터넷 주소) | 사진을 Supabase Storage에 올리고 받을 수 있는 주소를 돌려줍니다. 확장 C부터 사용합니다. |
| `js/upload.js` | `drawQrCode(element, url)` | QR 코드를 표시할 요소와 사진 URL | 화면에 그려진 QR 코드 | 휴대폰으로 사진 주소를 열 수 있는 QR 코드를 표시합니다. 확장 C부터 사용합니다. |

확장 A의 호출은 `initApp()` → 컷 수 선택 → `startSession()` → `runCaptureSequence()` → 컷마다 `runCountdown()` 및 `captureShot(video)` → `renderResult()` → `makeStrip(shots)` → `showPreview(strip)` 순서입니다. 어느 단계에서든 오류가 나면 촬영을 중단하고 `showError(message)`로 안내합니다. `처음으로`는 `resetSession()`을 호출합니다.

### 확장 B 필터 정의와 호출 흐름

`js/filters.js`의 전역 `FILTERS` 목록은 아래 여섯 항목을 이 순서대로 제공합니다. `name`은 상태와 함수 호출에 사용하는 값이고, `label`은 버튼에 표시하는 한국어 이름입니다. 각 `apply(r, g, b)`는 한 픽셀의 입력 RGB 채널(각 0~255)을 받아 변환된 RGB 채널을 돌려줍니다.

| name | label | `apply(r, g, b)` 변환 |
|---|---|---|
| `original` | 원본 | `(r, g, b)` 그대로 반환 |
| `grayscale` | 흑백 | `Y = 0.299r + 0.587g + 0.114b`를 계산해 `(Y, Y, Y)` 반환 |
| `sepia` | 세피아 | 표준 세피아 계수로 각 채널을 계산: `R' = 0.393r + 0.769g + 0.189b`, `G' = 0.349r + 0.686g + 0.168b`, `B' = 0.272r + 0.534g + 0.131b` |
| `warm` | 따뜻하게 | `(r + 20, g + 8, b - 12)` |
| `cool` | 시원하게 | `(r - 12, g + 4, b + 20)` |
| `bright` | 화사하게 | `(r + 30, g + 30, b + 30)` |

모든 변환 결과는 채널별로 반올림한 뒤 0~255 범위로 제한합니다. 흑백과 세피아 계산 결과도 같은 규칙을 적용합니다. `applyFilter(canvas, filterName)`은 이 변환을 캔버스의 각 픽셀에 적용하되 전달받은 캔버스를 수정하지 않고, 원본과 같은 너비·높이의 새 캔버스를 반환합니다. `original`도 원본 캔버스 자체를 돌려주지 않고 복사된 새 캔버스를 반환합니다.

앱 상태에 `state.filter`를 두고 기본값은 `original`로 합니다. 결과 화면 진입 시 `FILTERS`를 순회해 버튼을 동적으로 만들며, 버튼 선택은 `state.filter`를 갱신한 뒤 `renderResult()`를 바로 실행합니다. 모든 컷 촬영이 끝난 직후에도 `renderResult()`를 실행해 우선 원본 프레임을 보여 줍니다. `renderResult()`는 매번 원본 `state.shots`의 각 사진에 `applyFilter()`를 적용해 새 사진 캔버스 목록을 만들고, 그 목록을 `makeStrip()`에 전달해 프레임을 새로 생성합니다. 따라서 필터를 바꾸어도 이전 필터 결과에 효과가 누적되지 않습니다.

필터는 프레임을 만든 다음 완성 캔버스 전체에 적용하지 않습니다. **촬영 사진 → 사진별 필터 캔버스 → `makeStrip()`으로 프레임 생성** 순서이므로 흰 프레임 바탕, `인생네컷` 글씨와 날짜는 필터 입력에 포함되지 않아 원래 색과 모양을 유지합니다.

## 5. 데이터 흐름

```text
카메라 영상 → 원본 촬영 사진들(state.shots)
  → applyFilter()로 사진별 새 캔버스 생성(state.filter 선택)
  → makeStrip()으로 프레임 재생성(바탕·글씨는 필터 제외)
  → Supabase Storage 사진 파일 → 사진 URL → QR 코드
```

1단계에서는 카메라 영상에서 촬영한 사진까지 확인합니다(실제 기기/브라우저 검증은 미완료). 확장 A에서 세로 프레임, 확장 B에서 필터, 확장 C에서 저장과 QR 코드를 이어 붙입니다.

## 6. 지켜야 할 결정

| 결정 | 의미 |
|---|---|
| 카메라 사용 조건 | 브라우저 보안 정책상 카메라는 HTTPS 주소 또는 내 PC에서 직접 연 파일(`file://`)에서만 켤 수 있습니다. 일반 HTTP 웹 주소에서는 동작하지 않을 수 있습니다. |
| 스크립트 불러오는 순서 | `<script type="module">`은 쓰지 않습니다. `index.html`의 모든 화면 요소 뒤에 일반 `<script>` 태그로 `camera.js` → `frame.js` → `filters.js` → `app.js` 순서로 불러옵니다. 각 파일이 앞 파일에서 정의한 함수를 사용할 수 있도록 이 순서를 지킵니다. |
| 사진 보관 기간 | Supabase Storage에 올린 사진은 학생이 직접 삭제하기 전까지 자동으로 지우지 않습니다. 확장 C에서는 삭제 방법과 QR 주소의 접근 범위도 함께 정해 사용자가 사진을 관리할 수 있게 합니다. |
